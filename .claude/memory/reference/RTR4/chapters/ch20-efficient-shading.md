# Ch20 Efficient Shading 高效着色

**核心问题**：如何用更少的资源做更多着色？

---

## 20.1 延迟着色（Deferred Shading）

**核心思想**：几何阶段和光照阶段分离。

**步骤**：
1. **几何阶段**：渲染所有不透明物体到 **G-buffer**（位置、法线、材质、深度）
2. **光照阶段**：对每个像素做光照累加

**G-buffer 内容**（典型）：
- 位置（float3 或深度重构）
- 法线（float3）
- 材质 ID（索引）
- 基础色（float3）
- 粗糙度/金属度（float）
- 速度（float2，运动向量）

**优点**：
- 光源数与开销无关
- 避免 overdraw 计算
- 自然支持 OIT

**缺点**：
- G-buffer 带宽大
- 不适合透明物体
- MSAA 难（需要 Forward+ 或 Forward 2.5）

**变体**：
- **Light Pre-Pass**（light prepass）
- **Deferred Texturing**（Ch20.5）
- **Clustered Forward**（Ch20.4）

---

## 20.2 贴花渲染（Decals）

**核心**：将纹理/材质投影到其他表面。

**实现**：
- 投影框（box 或 frustum）
- 渲染时裁剪到接收物体表面
- 用于弹孔、污渍、标识

**类型**：
- **静态贴花**：烘焙到静态几何
- **动态贴花**：运行时生成

---

## 20.3 分块着色（Tiled Shading）

**核心**：把屏幕分成小块（Tiled），每块找出影响光源。

**步骤**：
1. **光源剔除**：每块找出可见光源
2. **前向 + 块光源**：在块内做前向着色
3. 避免每像素遍历所有光源

**Tile 尺寸**：通常 16×16 或 32×32 像素。

**优点**：
- 光源数无界
- 比全 forward 快
- 比 full deferred 灵活

**缺点**：
- 光源剔除的 CPU 开销
- tile 边界处理

---

## 20.4 聚类着色（Clustered Shading）

**核心**：3D 网格（Clustered），把 3D 空间分成 cluster。

**步骤**：
1. 屏幕分块（2D tile）
2. 每块在 Z 方向分多个 cluster
3. 每 cluster 找出影响光源
4. 每像素使用 cluster 光源列表

**优点**：
- 处理大型光源（点光有范围）
- 适合大量光源
- 现代游戏首选

**代表**：Unreal Engine, Doom (2016)

---

## 20.5 延迟纹理（Deferred Texturing）

**核心**：把纹理采样延迟到光照阶段。

**优点**：
- G-buffer 更紧凑（只存材质 ID）
- 纹理采样仅对可见像素
- 适合大量材质

**缺点**：
- 光照阶段需要知道像素位置
- 复杂材质 shader 难

---

## 20.6 对象空间和纹理空间着色

**对象空间**：
- 着色在物体局部坐标
- 适合程序化纹理

**纹理空间**：
- 在 UV 空间渲染
- 用于贴花、sub-surface scattering
- 通常 1 quad 覆盖物体 UV

**纹理空间扩散（Ch14.6.4）**：在 UV 空间做次表面散射的卷积。
